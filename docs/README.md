# AgentDrive docs — what governs what

## The contract

| Question | Where |
| --- | --- |
| What is the v0 surface, and what are its cross-cutting rules? | [`agentdrive-v0-api-contract-reset.md`](agentdrive-v0-api-contract-reset.md) — **the governing document** |
| Which operations exist, with what preconditions and idempotency class? | `src/agentdrive/api/v0-operations.json` (package data, not a doc) |
| What does the served spec actually say? | `tests/openapi.golden.json`, regenerated by `python -m agentdrive.scripts.dump_openapi` |
| What is enforced, as opposed to described? | `tests/conformance/` — manifest ↔ served-spec equality, scope enforcement, isolation, and one end-to-end journey |

When those disagree, the conformance suite is right: it runs against the
mounted app, while a document is only a claim about it.

## Using AgentDrive from code

[`agentdriveSDK.md`](agentdriveSDK.md) is the SDK guide the running service
also serves. The generated clients live in
[`tokencanopy/agentdrive-sdk`](https://github.com/tokencanopy/agentdrive-sdk),
built from `tests/openapi.golden.json`.

## Design history

Source comments cite design documents by path and section, such as
`docs/superpowers/specs/2026-08-14-agentdrive-direct-transfer-session-design.md`.
Those were written while AgentDrive was developed inside the Token Canopy
product repository and were not carried into this one; a citation names the
reasoning behind the code it sits beside, and the code and its tests are the
authority. Open an issue if a decision needs explaining and the code does not
carry it.
